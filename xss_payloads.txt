SESSION 26: CLIENT-SIDE ATTACK PAYLOADS
==================================================

1. REFLECTED XSS
* Payload Used: <script>alert('XSS')</script>
* Concept: Why does this attack disappear when you refresh the page?
Answer: Reflected XSS is non-persistent. The malicious script is delivered via the immediate HTTP request parameters and immediately processed in the response DOM by the server. Because the application server does not save this input to a database, refreshing the page issues a clean request without the payload parameter, causing it to clear.

2. STORED XSS (Cookie Theft)
* Cookie Value Stolen: session_id=admin_secret_99812_do_not_share
* Payload Used: <script>alert(document.cookie)</script>

3. CROSS-SITE REQUEST FORGERY (CSRF)
* Malicious URL Crafted: http://localhost:8081/transfer?to=Attacker&amount=5000
* Concept: What is the primary defense against CSRF?
Answer: The primary defense against CSRF is using Anti-CSRF Tokens (Unique, unpredictable cryptographically secure tokens associated with the user's current session). The server includes this token in state-changing requests and validates it before processing the transaction, preventing unauthorized hidden requests from succeeding.
